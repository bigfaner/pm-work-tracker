# Proposal: System UX Optimization Batch

## Problem

PM Work Tracker 存在两类问题：

**阻断性 Bug（#8）：** member 角色用户完全无法使用系统，需立即修复。

**体验优化（#1-#7, #9-#16）：** 影响日常操作效率的功能缺陷和交互问题，涵盖状态流转、表单交互、删除、过滤、排序等方面。

### Evidence

- #1: 状态流转失败时仅显示2秒 tooltip 提示"暂无可用流转"，用户无法理解失败原因（影响：5名PM用户，每日约10次触发，每次需30秒猜测原因，基于 PM 团队反馈）
- #2: 子事项编辑表单缺少开始时间字段，后端已支持但前端未暴露（影响：5名PM用户，每日约5次编辑子事项需修改开始时间，需绕道详情页操作，基于 PM 团队反馈）
- #3: 主事项无删除功能（仅有归档），子事项删除未暴露为 API（影响：5名PM用户，每周约3次需要删除误建事项，目前只能联系管理员手动处理，基于 PM 团队反馈）
- #4: 待办→子事项转换表单的描述字段可编辑，用户可能误修改不应修改的内容（影响：5名PM用户，约10%的转换操作因误改描述导致数据不一致，基于 PM 团队反馈）
- #5: 子事项列表无排序，数据以插入顺序展示（影响：5名PM用户，每日约15次查看子事项列表，需手动寻找最新子事项，基于 PM 团队反馈）
- #6: 新增表单关闭后不清空字段，再次打开显示残留数据（影响：5名PM用户，约20%的新建操作受残留数据干扰需手动清空，基于 PM 团队反馈）
- #7: 待办→主事项/子事项转换表单的负责人和优先级字段无前端校验，提交后由后端报错（影响：5名PM用户，约30%的新建操作因未选负责人而提交失败，基于 PM 团队反馈）
- #8: 内置 member 角色用户登录后获取不到任何权限（阻断性：3名 member 角色用户完全无法使用系统任何功能）
- #9: 用户无法将子事项从一个主事项移动到另一个主事项，需要手动删除并重建（影响：5名PM用户，每周约2次需要重组子事项归属，需手动删除后重建并重新分配编号，基于 PM 团队反馈）
- #10: 卡片视图和表格视图的过滤器为单选，不支持多状态筛选，且不穿透子事项（影响：5名PM用户，每日约8次使用过滤，多状态需求约占40%的过滤操作，基于 PM 团队反馈）
- #11: 事项清单页面中已完成/已关闭等终态主事项与进行中的主事项混在一起，用户需手动区分（影响：5名PM用户，每日约10次查看清单页面，约60%为终态主事项干扰视线，基于 PM 团队反馈）
- #12: 整体进度页面展示所有主事项，无法按状态过滤，大量已关闭事项占据页面空间（影响：5名PM用户，每日约8次查看整体进度页面，约70%为已关闭事项，基于 PM 团队反馈）
- #13: 整体进度页面甘特图时间起点不正确，所有事项最早开始时间为4月12日，但甘特图起始日期显示为3月30日，中间存在大片空白区域（影响：5名PM用户，每日约8次查看进度页面，空白区域导致可视范围缩小约30%，基于 PM 团队反馈）
- #14: 整体进度页面甘特图在 macOS 系统下底部水平滚动条消失，无法横向滚动查看完整时间范围（影响：所有使用 macOS 的用户，约3人，完全无法查看超出可视区域的事项，基于 PM 团队反馈）
- #15: 左侧菜单栏上方的团队下拉选择器展示所有团队，未根据当前用户的权限过滤，用户可能误选无权限团队后才发现无法操作（影响：5名用户，涉及多团队协作场景，约每周2次误选，基于 PM 团队反馈）
- #16: 每周进展页面展示了大量终态且近期无活跃的主事项，用户需手动跳过这些无关事项才能找到本周需关注的内容（影响：5名PM用户，每周约5次查看周进展页面，约50%内容为终态无活跃事项，基于 PM 团队反馈）

### Urgency

这些问题直接影响 PM 和团队成员的日常操作效率。#8 权限 bug 导致 member 角色用户完全无法使用系统。

## Proposed Solution

分两阶段实施 16 项优化：

**阶段一（Bug 修复 + 体验增强）：** 修复权限 bug，完善状态流转提示，补全表单校验和交互细节，统一排序和清空行为，修复团队选择器权限过滤和每周进展页面过滤。

**阶段二（新功能 + Bug 修复）：** 新增子事项移动、过滤穿透、清单终态排序、进度页面状态过滤功能，修复甘特图时间起点和 macOS 滚动条问题。

### Innovation Highlights

- 过滤穿透：负责人筛选时，如果某子事项匹配，则连带展示其主事项。实现方式为增强现有 ViewService.TableView 的内存过滤逻辑——先按原有条件查出主事项列表，再对每条主事项的子事项做二次匹配，将仅因子事项匹配而出现的主事项追加到结果集，避免引入新的 SQL 查询模式
- 子事项移动时自动重新编号，保持编号与父事项的一致性

## Requirements Analysis

### Key Scenarios

**状态流转（#1）：**
- 用户点击状态流转按钮 → 后端返回不可流转原因 → 使用 Alert 组件在操作区域下方展示行内错误消息（如"该主事项下还有未完成的子事项，无法关闭"）
- 终态流转保留确认对话框

**编辑子事项开始时间（#2）：**
- 用户打开子事项编辑弹窗 → 看到"开始时间"字段 → 修改并保存

**PM 删除事项（#3）：**
- PM 点击删除按钮 → 确认对话框 → 软删除主事项及其所有子事项
- 非 PM 角色看不到删除按钮
- 子事项也可单独删除

**转换表单（#4, #7）：**
- 待办→子事项：开始时间默认当天，描述字段置灰且不可编辑
- 待办→主事项/子事项：负责人和优先级为必填，未填时提交按钮禁用

**子事项排序（#5）：**
- 主事项详情页的子事项列表按创建时间倒序（最新在前）

**表单清空（#6）：**
- 所有新增/转换表单关闭时（含取消）自动清空所有字段

**Member 角色权限（#8）：**
- 修复前：member 登录后只能看到空白页面；修复后：member 能看到其权限范围内的菜单和功能
- member 角色用户登录后能获取到该角色的权限列表

**移动子事项（#9）：**
- 用户在子事项详情/编辑界面选择"移动到其他主事项" → 选择目标主事项 → 子事项通过目标父项的 NextSubCode 获得新编号并关联到新主事项
- 源父项剩余子事项不做重编号，保持原有编号不变
- 状态和负责人保持不变
- 目标主事项为已关闭状态时禁止移动；源主事项和目标主事项相同时禁止操作
- 源父项下所有子事项移出后，源父事项保留（变为无子事项的主事项），不做特殊处理
- 移动操作在 DB 事务中执行，防止并发移动导致编号冲突

**过滤穿透（#10）：**
- 状态过滤器改为多选（Checkbox Group 或 Multi-Select）
- 负责人过滤器：选中负责人 A 时，展示 A 负责的主事项 + 含 A 负责子事项的主事项（连同该子事项一起展示）
- 因子事项匹配而展示的主事项，在卡片/行上标注"因子事项匹配"标识，帮助用户理解为什么该主事项出现在结果中。该主事项下仅展示匹配的子事项，非匹配的子事项在过滤模式下折叠隐藏
- 状态和负责人过滤器均未选择时（零过滤状态），展示全部事项（等同于无过滤）
- 卡片视图和表格视图统一支持

**事项清单排序（#11）：**
- 事项清单页面中，处于终态（已关闭、已完成等）的主事项自动排在列表最后，非终态主事项按原有顺序展示
- 排序在服务端完成，不影响前端分页逻辑

**整体进度页面过滤（#12）：**
- 整体进度页面支持按主事项状态过滤（多选 Checkbox Group），不支持负责人过滤（该页面聚焦全局进度概览而非人员分配）
- 首次加载时"进行中"复选框默认选中
- 处于终态的主事项在过滤结果中排在最后
- 用户取消所有状态复选框后，展示全部事项

**甘特图时间起点修复（#13）：**
- 甘特图时间轴起始日期应根据实际数据的最早开始时间自动计算，不留空白区域
- 建议：取所有可见主事项中最早开始时间的前1天作为起始日期，最晚结束时间的后1天作为终止日期

**甘特图 macOS 滚动条修复（#14）：**
- 修复 macOS 系统下甘特图底部水平滚动条不显示的问题
- macOS 默认隐藏滚动条（系统设置"滚动时"模式），需通过 CSS 确保滚动条始终可见或在 hover 时明确显示

**团队选择器权限过滤（#15）：**
- 左侧菜单栏上方的团队下拉选择器仅展示当前用户有权限的团队
- 后端团队列表 API 需根据用户身份过滤，仅返回用户所属或有权限的团队
- 若用户仅有一个团队，下拉选择器可省略或固定展示该团队名称

**每周进展页面过滤（#16）：**
- 每周进展页面不展示处于终态且本周和上周都没有活跃事项的主事项
- "活跃"定义：本周或上周内有过状态变更、子事项新增/编辑、或进度更新的主事项
- 非终态主事项始终展示，不受此规则影响
- 该过滤在后端数据查询阶段完成，前端无需额外处理

### Non-Functional Requirements

- 删除操作需二次确认
- 过滤穿透查询性能：主事项 + 子事项联合过滤应在 500ms 内返回（当前生产环境数据量约 200 主事项 + 800 子事项，性能基准 1000+5000 已覆盖约 5 倍余量）
- 过滤穿透在内存过滤阶段完成后、分页之前执行。当前不分页（一次性返回全量），若未来引入分页需重新评估

### Constraints & Dependencies

- 后端已支持子事项 startDate 更新（SubItemUpdateReq.StartDate）
- 后端 TableView DTO 已支持状态多选（TableFilter.Status []string）
- 删除需新增权限码（main_item:delete, sub_item:delete）
- 级联删除必须在单个 DB 事务内执行：先批量软删除子事项，再软删除主事项；已软删除的子事项跳过联动评估
- 子事项编号重新生成依赖现有的编号服务

## Alternatives & Industry Benchmarking

### Industry Solutions

项目管理工具（Jira, Linear, Asana）普遍支持：批量删除、子任务移动、多状态过滤。具体参考：

- **#1 状态流转**：Jira 在工作流状态转换失败时展示行内错误提示（而非 tooltip），明确列出具体不满足的前置条件（如"子任务未全部完成"）。本提案采用相同模式（Alert 行内错误消息）。
- **#6 表单清空**：Linear 的创建对话框关闭后自动清空所有字段，用户再次打开时看到空白表单。本提案要求所有新增/转换表单在关闭时（含取消）清空字段。
- **#9 子事项移动**：Notion 的子页面移动功能提供搜索选择器 + 确认对话框，移动后自动更新页面层级和编号。本提案采用类似模式（选择目标主事项 + 自动重新编号）。
- **#10 过滤穿透**：Linear 使用 Checkbox Group 支持多状态同时筛选，并在筛选结果中高亮匹配项；Asana 的子任务搜索支持"穿透"到子任务层级并展示其父任务。本提案采用多选 Checkbox Group + 子事项匹配时连带展示主事项的模式。

## Feasibility Assessment

### Technical Feasibility

- 所有改动在现有技术栈内完成，无新依赖
- #9 子事项移动：需新增 API + 前端 UI + 编号重生成，中等工作量
- #10 过滤穿透分解：(a) 后端增强 ViewService 内存过滤逻辑支持穿透，约1天；(b) 前端状态过滤器改为多选 Checkbox Group，约0.5天；(c) 前端负责人过滤对接穿透逻辑 + 视觉标识，约0.5天；(d) 卡片视图适配（ItemViewPage 从客户端过滤切换到使用 TableView API），约0.5天。阶段二合计约2.5-3天

### Resource & Timeline

- 阶段一 10 项：#1-#2 各0.5天，#3 含事务逻辑约1天，#4-#7 各0.5天，#8 分两步：(a) 排查阶段 0.5天：查询 pmw_team_members 确认根因，若 role_key 在 seed 数据中缺失则修复 seed 逻辑（约0.5天），若为已有数据未回填则补充迁移脚本（约0.5天）。排查后根据根因选择唯一路径，不做运行时分支。#15 团队选择器权限过滤约0.5天。#16 每周进展过滤约0.5天。阶段一合计约5-6天
- 阶段二 6 项：新功能开发，预计 4-5 天（#9 移动约1天，#10 过滤穿透约2-3天，#11 清单排序约0.5天，#12 进度页面过滤约0.5天，#13 甘特图时间起点约0.5天，#14 macOS 滚动条约0.5天）

### Dependency Readiness

- 后端已有子事项 startDate 更新、TableFilter 多选支持
- 编号服务已存在（用于创建时的编号生成）

## Scope

### In Scope

**阶段一：**
1. 状态流转失败时展示后端返回的错误消息（替代 tooltip）
2. 子事项编辑表单添加开始时间字段
3. PM 可软删除主事项（级联子事项）和子事项，需确认对话框；同步更新 seed 数据添加 main_item:delete、sub_item:delete 权限码（约 4 行变更于 migration/rbac.go）；删除时在现有 status_history 表中记录删除事件
4. 待办→子事项表单描述字段添加置灰样式（disabled appearance）
5. 主事项详情页子事项列表倒序排列（ORDER BY id DESC）
6. 所有新增/转换表单关闭时清空字段
7. 转换表单（待办→主事项/子事项）负责人和优先级必填校验
8. 修复 member 角色用户登录后获取不到权限的 bug
15. 团队下拉选择器仅展示当前用户有权限的团队（后端 API 过滤 + 前端适配）
16. 每周进展页面隐藏终态且本周/上周无活跃事项的主事项（后端过滤）

**阶段二：**
9. 子事项移动到其他主事项（重新编号，保留状态和负责人）
10. 状态过滤器改为多选 + 负责人过滤穿透子事项（卡片视图和表格视图统一支持）
11. 事项清单页面终态主事项排序到最后（服务端排序）
12. 整体进度页面支持按状态过滤，默认仅展示进行中状态，终态主事项排在最后
13. 甘特图时间轴起点根据实际数据自动计算，消除空白区域
14. 修复 macOS 下甘特图水平滚动条不显示问题（CSS 修复）

**阶段一完成标准：** 全部 10 项功能的 SC 通过验证（共12条），前端测试全量通过，member 角色用户可正常登录并使用权限范围内的功能，团队选择器仅展示有权限的团队，每周进展页面不展示终态且无近期活跃的主事项。

**阶段二完成标准：** 全部新增 SC 通过验证；子事项移动功能通过手动冒烟测试（移动、边缘场景）；过滤穿透功能通过前端测试并在 1000+5000 数据量下性能达标；事项清单页面终态排序正确；整体进度页面默认过滤仅展示进行中状态且终态排序正确；甘特图时间起点无空白区域；macOS 下水平滚动条可见；前端全量测试无回归。

### Out of Scope

- 硬删除（永久清除数据）
- 独立的删除审计 UI 或通知推送（status_history 记录已包含在范围内）
- 批量操作（批量删除、批量移动）
- 子事项移动历史记录
- 卡片视图的拖拽排序
- 新增权限码之外的其他 seed 数据更新（由 RBAC 提案覆盖）

### Cross-Phase Dependencies

- Phase 2 的移动对话框需要与 Phase 1 (#6) 相同的表单清空模式。建议在 Phase 1 实现时将表单重置逻辑提取为共享 hook（如 useResetForm），Phase 2 直接复用。
