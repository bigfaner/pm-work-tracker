## Conventions Established

1. **Server-side milestone filtering**: Milestone filter sends milestoneKey to backend API rather than filtering client-side. The special 'unassigned' value maps to null milestone_key. New filter helpers go in filter_helpers.go following the assigneeFilter pattern.
2. **Sentinel values for unassigned selects**: Use '__unassigned__' as sentinel value in SelectItem to distinguish from real bizKeys. Convert to null/empty before sending to API.
3. **Shared query reuse**: When multiple components on the same page need the same data (e.g., milestone options for both filter and dialog), share a single query rather than fetching independently.
4. **3-state sort toggle**: Sortable columns use a 3-state cycle (none -> asc -> desc -> none) with lucide-react icons (ChevronsUpDown/ArrowUp/ArrowDown) for visual feedback.
5. **Error state in Select trigger**: API failure for Select options shows error text in the trigger element (disabled), not in dropdown content.

- **[4.3] Column rendering pre-existing**: Tech design described inserting a new milestone column, but column rendering and filtering were already implemented in a prior phase. Task 4.3 only added the sort feature.
- **[4.1] Badge style**: Tech design did not specify badge styling details. Implementation used existing Badge component with default variant + rounded-full class for milestone name badges on MI list items.
