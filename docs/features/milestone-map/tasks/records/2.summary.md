### 4. Conventions Established

- **WithRepos() functional option pattern**: Used by WithMilestoneRepos() to inject cross-domain repos into existing service without changing constructor signature. Future cross-domain dependencies should follow this pattern.
- **Handler VO enrichment for computed fields**: calcOverallProgress, calcCompletion, countRelatedMIs, MilestoneName are all computed/enriched at handler layer via batch repo calls, not persisted. Future computed fields follow this pattern.
- **Cascade delete in transaction**: SD-007 pattern — clear MI bindings -> soft-delete children -> soft-delete parent, all in one transaction. Applies to both MilestoneMap and Milestone delete/cancel.
- **ParseBizKeyParam for route resolution**: Both MilestoneMapHandler and MilestoneHandler use ParseBizKeyParam (not ResolveBizKey) since services have GetByBizKey methods.
- **nolint:dupl on structurally identical handler methods**: Delete, ChangeStatus, AvailableTransitions follow identical patterns by convention; dupl lint suppressed with directive.

### 5. Deviations from Design

- **No MilestoneVO user name enrichment**: Tech design lists UserRepo dependency for MilestoneHandler, but MilestoneVO has no user name fields (no creator/assignee). Implementation correctly omits UserRepo from MilestoneHandler constructor.
- **MilestoneMap computed fields at handler layer**: Tech design places computed fields (milestoneCount, itemCount, overallProgress) in the service layer description, but implementation computes them in the handler VO builder via direct repo calls — consistent with how other handlers enrich VOs.
- **SoftDeleteByMap signature change**: Changed from milestoneMapID uint to milestoneMapBizKey int64 to match the stored milestone_map_key column and ListByMap parameter type.
- **No separate VO/DTO files**: Tech design lists milestone_vo.go and milestone_dto.go as separate files. VO structs are defined in the handler files and DTO structs inline, following the project's actual convention (not separate files).
- **Task 2.9 was verification-only**: Router wiring was completed incrementally by 2.7 and 2.8 rather than as a separate wiring step.
