# 1.4: Milestone status system, permissions, and error types

## Description
Implement the milestone status system (definitions, transitions, getter functions), register 4 milestone permission codes in the existing Registry, and define all milestone-specific error types. These are standalone packages with no cross-feature dependencies.

## Reference Files
- docs/features/milestone-map/design/tech-design.md — Status System (Status Definitions, Transitions, Available Transitions), Permission System (Registry Addition), Error Handling
- docs/features/milestone-map/prd/prd-spec.md — Status value mapping tables

## Acceptance Criteria
- [ ] `MilestoneMapStatuses` map defines all 6 states (planning/reviewed/ready/executing/completed/cancelled) with correct terminal flags
- [ ] `MilestoneStatuses` map defines all 4 states (not_started/in_progress/completed/cancelled) with correct terminal flags
- [ ] Transition maps match PRD: `MilestoneMapTransitions` (5 entries) and `MilestoneTransitions` (3 entries); `GetMilestoneMapStatus`/`GetMilestoneStatus` getter functions work
- [ ] 4 milestone permissions registered in `permissions/codes.go` Registry: milestone:create, milestone:read, milestone:update, milestone:delete
- [ ] All 8 error types defined matching tech-design Error Handling table: ErrMapIsTerminal, ErrDuplicateMilestoneName, ErrMilestoneHasNonTerminalItems, ErrMapHasNonTerminalMilestones, ErrTerminalItemCannotMove, ErrTerminalMilestoneCannotReceive, ErrMapCannotDelete, ErrMilestoneCannotDelete
