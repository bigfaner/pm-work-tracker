# 2.1c: MilestoneMap Complex Operations

## Description

Implement the complex MilestoneMap operations: cascade Delete, status transitions (5-state), AvailableTransitions, and computed fields (milestoneCount, itemCount, overallProgress).

## Reference Files

- `design/api-handbook.md` — Delete, ChangeStatus, AvailableTransitions endpoints
- `design/tech-design.md` — Computed Fields, status transition rules
- `backend/internal/pkg/status/transition.go` — Transition pattern
- `backend/internal/pkg/repo/transactor.go` — Transaction pattern
- `backend/internal/service/sub_item_service.go` — Soft-delete + transaction pattern

## Acceptance Criteria

- [ ] Delete endpoint: cascade soft-delete map + soft-delete all milestones + unbind all MIs in one transaction
- [ ] ChangeStatus: 5-state transition (planning→reviewed→ready→executing→completed), validate via transition rules
- [ ] AvailableTransitions: return valid next states for current map status
- [ ] calcOverallProgress: `SELECT AVG(completion_pct) FROM pmw_main_items WHERE milestone_key IN (SELECT biz_key FROM pmw_milestones WHERE milestone_map_key = ? AND deleted_flag = 0) AND deleted_flag = 0`
- [ ] calcMilestoneCount: count milestones where milestone_map_key = map's bizKey and deleted_flag = 0
- [ ] calcItemCount: count main_items where milestone_key IN (milestones of this map) and deleted_flag = 0
- [ ] List computed fields now return real values instead of stubs
- [ ] Routes registered: DELETE, PUT status, GET available-transitions
- [ ] `just test` passes

## Implementation Notes

- Delete cascade: use DBTransactor for transaction. In one tx: SoftDelete map, call MilestoneRepo.DeleteByMap, then unbind MIs.
- Status states: planning, reviewed, ready, executing, completed (terminal).
- calcOverallProgress: return 0 if no items. Use raw SQL for the subquery.
- This task depends on MilestoneRepo existing — it will be created in 2.2a. If 2.2a hasn't run yet, stub the milestone repo calls and add a TODO.
