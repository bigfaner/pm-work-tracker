# 2.2: Milestone Repo + Service + Handler + Routes

## Description

Implement the full Milestone backend stack: GORM repository, service layer (with completion calculation, status transitions, soft-delete with MI unbinding), HTTP handlers, and route registration.

## Reference Files

- `design/tech-design.md` — MilestoneRepo, MilestoneService interfaces; Computed Fields
- `design/api-handbook.md` — All Milestone endpoints
- `backend/internal/repository/main_item_repo.go` — Repo interface pattern
- `backend/internal/service/main_item_service.go` — Service pattern

## Acceptance Criteria

- [ ] `repository/milestone_repo.go`: Interface with Create, FindByID, FindByBizKey, FindByBizKeys (batch), Update, ListByMap, ListByTeam (excludeCancelled), SoftDelete, DeleteByMap
- [ ] `repository/gorm/milestone_repo.go`: GORM implementation
- [ ] `service/milestone_service.go`: Interface + implementation with Create, Update, Get, GetByBizKey, ListByMap, ListByTeam, Delete (soft-delete + unbind MIs in transaction), ChangeStatus, AvailableTransitions, calcCompletion, countRelatedMIs
- [ ] `handler/milestone_handler.go`: Create, ListByMap, ListByTeam, Get, Update, Delete, ChangeStatus, AvailableTransitions handlers
- [ ] `handler/router.go`: Routes registered — nested under milestone-maps/:mapId for map-scoped ops, top-level under teams for team-scoped list
- [ ] ChangeStatus to `cancelled` auto-unbinds all associated MIs (sets milestone_key to null)
- [ ] calcCompletion returns 0 for milestones with no MIs
- [ ] `just test` passes for all new code

## User Stories

- Story 4a: PM 创建里程碑 (name + expectedEndDate, default not_started)
- Story 4b: PM 编辑里程碑信息 (concurrent edit conflict → 409)
- Story 4c: PM 删除里程碑 (soft-delete + unbind MIs in transaction)
- Story 5: PM 切换里程碑状态 (4-state transition, cancelled auto-unbinds)
- Story 7: 详情面板管理事项 (completion, relatedMICount)

## Implementation Notes

- calcCompletion: `SELECT AVG(completion_pct) FROM pmw_main_items WHERE milestone_key = ? AND deleted_flag = 0` → return 0 if no rows
- Delete transaction: soft-delete milestone, then `UPDATE pmw_main_items SET milestone_key = NULL WHERE milestone_key = ?` in same tx
- FindByBizKeys is critical for MainItem list enrichment (batch lookup, not N+1)
- ListByTeam for UF-4/5/6: exclude cancelled by default, return ordered by milestone_name
