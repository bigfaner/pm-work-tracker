# 2.3: MainItem milestoneKey Integration

## Description

Wire milestoneKey into the existing MainItem create/update/list flows. Handle BizKey parsing, team validation (milestone and MI must be in same team), and list response enrichment with milestoneName.

## Reference Files

- `design/tech-design.md` — MainItemService (Modified) section, DTO additions, list enrichment wiring
- `backend/internal/service/main_item_service.go` — Existing service to modify
- `backend/internal/handler/main_item_handler.go` — Existing handler to modify
- `backend/internal/vo/item_vo.go` — Existing VO to add milestoneKey/milestoneName fields

## Acceptance Criteria

- [ ] `MainItemCreateReq.MilestoneKey` parsed and validated: if non-nil, resolve to milestone ID, verify same team
- [ ] `MainItemUpdateReq.MilestoneKey` handled: nil=no change, non-nil=value (empty string=unbind)
- [ ] MainItem model: `MilestoneKey *int64` field with column `milestone_key`
- [ ] MainItem VO: add `MilestoneKey *string` and `MilestoneName string` fields
- [ ] List response enrichment: batch lookup milestones via `MilestoneRepo.FindByBizKeys`, set milestoneName; soft-deleted milestones show "--"
- [ ] Get single item also returns milestoneKey + milestoneName
- [ ] Existing MainItem tests still pass
- [ ] `just test` passes

## User Stories

- Story 6: PM 分配事项到里程碑 (bind via update)
- Story 6: PM 解绑事项 (clear milestoneKey)
- Story 7: 行内解绑 (set milestoneKey to null)
- Story 7: 快速添加事项 (create with milestoneKey pre-filled)
- Story 10: 软删除里程碑显示 "--" (enrichment handles not-found case)

## Implementation Notes

- This is a breaking change: modifies existing MainItem DTOs and VOs
- MilestoneKey on CreateReq is `*string` (optional, nullable bizKey)
- Validation: if MilestoneKey is provided, resolve to milestone, verify team match
- List enrichment: collect all non-nil milestoneKey values from results → batch FindByBizKeys → map to names
- Soft-delete display: if milestoneKey is non-nil but milestone not found in batch map → milestoneName = "--"
