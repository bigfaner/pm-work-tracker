# 2.5: Milestone service (CRUD + status transitions + BR-1/BR-5)

## Description
Implement MilestoneService interface and implementation with full CRUD, status transitions (enforcing BR-1, BR-4, BR-5), available transitions filtering, and computed fields (completion, relatedMICount).

## Reference Files
- docs/features/milestone-map/design/tech-design.md — Interfaces (MilestoneService), Available Transitions (服务层), Business Rules (BR-1, BR-4, BR-5), Computed Fields
- docs/features/milestone-map/prd/prd-spec.md — Milestone 状态机转换规则

## Acceptance Criteria
- [ ] `Create` enforces BR-5 (parent map not terminal), checks duplicate name via `ExistsByNameAndMap`, generates BizKey, sets status to `not_started`
- [ ] `Update` applies partial updates, enforces BR-5 (parent map not terminal for status-relevant fields)
- [ ] `Delete` enforces BR-4 (only not_started/cancelled), unbinds all associated MIs via `ClearMilestoneKeyByMilestone` in transaction
- [ ] `ChangeStatus` enforces BR-5 (parent map not terminal → reject), BR-1 (completed requires all MIs terminal), cancelled auto-unbinds MIs via `ClearMilestoneKeyByMilestone`
- [ ] `AvailableTransitions` returns empty list when parent map is terminal (BR-5); otherwise filters `completed` if MIs not all terminal (BR-1)
- [ ] `calcCompletion` returns average MI completion (0 for empty milestone); `countRelatedMIs` returns correct count

## User Stories
- Story 5: PM 创建里程碑 (Create + BR-5)
- Story 6: PM 编辑里程碑信息 (Update + BR-5)
- Story 7: PM 删除里程碑 (Delete + BR-4)
- Story 8: PM 切换里程碑状态 (ChangeStatus + BR-1, BR-5)
