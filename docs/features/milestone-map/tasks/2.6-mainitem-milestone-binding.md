# 2.6: MainItem milestone binding logic and VO enrichment

## Description
Add milestone binding/unbinding validation (BR-3, BR-5) to MainItemService.Update when `MilestoneKey` is modified. Implement MainItemVO enrichment to batch-load milestone names via `FindBatchByBizKeys`.

## Reference Files
- docs/features/milestone-map/design/tech-design.md — Business Rules (BR-3: 主事项移动约束, BR-5: 父层终态向下约束), MainItem List Enrichment
- backend/internal/service/main_item_service.go — existing Update method

## Acceptance Criteria
- [ ] `MainItemService.Update` enforces BR-3 when `req.MilestoneKey` is non-nil: terminal MI (completed/closed) cannot change milestone_key → returns `ErrTerminalItemCannotMove`
- [ ] BR-3 enforced: target milestone in terminal state (cancelled) cannot receive MI → returns `ErrTerminalMilestoneCannotReceive`; validation order: check MI status first, then target milestone
- [ ] BR-5 enforced: parent milestone map in terminal state prevents milestone_key changes on associated MIs
- [ ] MainItemVO enrichment in handler/service layer: collects non-null MilestoneKey bizKeys → calls `FindBatchByBizKeys` → populates `voItem.MilestoneName`
- [ ] Soft-deleted milestone sets `MilestoneName` to `"—"` in enriched VO
