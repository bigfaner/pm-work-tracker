# 2.8: Milestone handler (API endpoints)

## Description
Implement MilestoneHandler with 7 API endpoints following existing handler patterns. Handles nested route (`/milestone-maps/:mapId/milestones`) and direct access (`/milestones/:milestoneId`) patterns.

## Reference Files
- docs/features/milestone-map/design/tech-design.md — Handler Pattern, Router Wiring (Route Registration)
- docs/features/milestone-map/design/api-handbook.md — Milestone Endpoints (Create, ListByMap, ListByTeam, Get, Update, Delete, ChangeStatus, AvailableTransitions)
- backend/internal/handler/item_pool_handler.go — pattern reference

## Acceptance Criteria
- [ ] `Create` handler resolves `:mapId` param, binds `MilestoneCreateReq`, calls service (BR-5 guard in service), returns `MilestoneVO` with 201
- [ ] `ListByMap` handler resolves `:mapId`, returns milestones for the map (non-paginated, sorted by expected_end_date)
- [ ] `ListByTeam` handler binds query filters (`MilestoneTeamFilter`), returns filtered milestones with computed completion/relatedMICount
- [ ] `Update` handler binds partial `MilestoneUpdateReq`, calls service (BR-5 guard), returns updated `MilestoneVO`
- [ ] `Delete` handler calls service (BR-4 enforced), returns `{ "message": "deleted" }`
- [ ] `ChangeStatus` + `AvailableTransitions` handlers proxy to service with proper route param resolution

## User Stories
- Story 5: PM 创建里程碑 (Create)
- Story 6: PM 编辑里程碑信息 (Update)
- Story 7: PM 删除里程碑 (Delete)
- Story 8: PM 切换里程碑状态 (ChangeStatus + AvailableTransitions)
