# 2.6: Remove IsSuperAdmin from VO/DTO response types

## Description

Remove `IsSuperAdmin` field from all backend response DTOs:
- `vo/user_vo.go` — `AdminUserDTO` struct
- `dto/auth.go` — `LoginResponse` struct
- `service/role_service.go` — `UserInfo` struct (if it has the field)

The `json:"isSuperAdmin"` tag is removed so the field no longer appears in API responses. The backend model `User.IsSuperAdmin` is kept — only the API-facing types change.

## Reference Files

- `design/tech-design.md` — Cross-Layer Data Map
- `backend/internal/vo/user_vo.go` — `AdminUserDTO`
- `backend/internal/dto/auth.go` — `LoginResponse`
- `backend/internal/service/role_service.go` — `UserInfo`
- `design/api-handbook.md` — Breaking Changes: Response Field Removal

## Acceptance Criteria

- [ ] No `json:"isSuperAdmin"` tags in any response DTO
- [ ] No `IsSuperAdmin` field in `AdminUserDTO`, `LoginResponse`, or `UserInfo`
- [ ] Backend compiles: `cd backend && go build ./...`
- [ ] Tests pass: `cd backend && go test ./...`

## User Stories

- Story 5: Frontend no longer receives `isSuperAdmin` from API responses
- Security: `IsSuperAdmin` not exposed through API, reducing information leakage

## Implementation Notes

Remove the field and any code that populates it in handlers/services. The `User.IsSuperAdmin` model field and `is_super_admin` DB column are kept — only the API-facing DTOs change. Handlers that set `IsSuperAdmin` on response structs need to remove those assignments.
