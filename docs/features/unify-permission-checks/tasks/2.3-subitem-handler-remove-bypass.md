# 2.3: Sub-item handler: remove isPMOrSuperAdmin and assignee checks

## Description

Remove the `isPMOrSuperAdmin()` function and all assignee ownership checks from `sub_item_handler.go`. The `Update` and `ChangeStatus` handlers currently check `if !isPMOrSuperAdmin { if item.AssigneeKey != callerBizKey → ErrForbidden }`. Remove these checks entirely — authorization is now enforced by `RequirePermission("sub_item:update")` and `RequirePermission("sub_item:change_status")` middleware.

## Reference Files

- `design/tech-design.md` — Error Path Migration > Removed: Assignee ownership checks
- `backend/internal/handler/sub_item_handler.go` — `isPMOrSuperAdmin()` (lines ~35-50), assignee checks (lines ~157-169, ~211-223)

## Acceptance Criteria

- [ ] `isPMOrSuperAdmin()` function deleted
- [ ] No assignee ownership checks (`AssigneeKey != callerBizKey`) in Update or ChangeStatus handlers
- [ ] Backend compiles: `cd backend && go build ./...`
- [ ] Handler tests pass: `cd backend && go test ./internal/handler/...`

## User Stories

- Story 1: Custom role with `sub_item:update` can edit any sub-item → 200 (core fix, AC1)
- Story 2: Custom role with `sub_item:change_status` can change status of any sub-item → 200 (core fix, AC2)

## Implementation Notes

Delete `isPMOrSuperAdmin()` function entirely. In `Update` handler, remove the `if !isPMOrSuperAdmin(c)` block (lines ~157-169). In `ChangeStatus` handler, remove the corresponding block (lines ~211-223). These are the core fixes that enable custom roles to use their granted permission codes.
