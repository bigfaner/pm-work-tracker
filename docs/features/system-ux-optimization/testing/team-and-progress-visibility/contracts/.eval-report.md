## Revision Guidance

The contracts pass at 880/1000. The following revisions would improve quality toward a higher score:

### Priority 1 -- Fact Table (affects Completeness, Fact Alignment)

All contracts lack a structured fact table. Add a `## Fact Table` section to each contract mapping journey facts to contract fields:

```markdown
## Fact Table
| Fact | Source | Contract Field |
|------|--------|---------------|
| User sees only permitted teams | Story 10 AC1 | Outcome "success" > Preconditions |
| Session expiry redirects to login | Web surface mandatory | Outcome "session-expired" |
```

### Priority 2 -- Step 3 Activity Enumeration (affects Completeness, Precondition Exclusivity)

Step 3 precondition should enumerate all activity types to match the journey:
- Current: "no activity in the current or previous week"
- Revised: "no activity (status changes, sub-item updates, or progress updates) in the current or previous week"

### Priority 3 -- Step 4 Validation Outcome (affects Semantic Purity, Surface Fitness, Fact Alignment)

The `validation-error` outcome in Step 4 is mismatched to the listing endpoint. Revise to either:
- Remove it if no query parameters can be invalid on GET /api/v1/teams, or
- Change to a realistic validation scenario (e.g., invalid pagination parameter, malformed query filter).

### Priority 4 -- HTTP Status Codes (affects Semantic Purity)

In Step 4, replace protocol-specific codes with semantic descriptions:
- "HTTP 401 with error code UNAUTHORIZED" -> "The API returns an authentication error"
- "HTTP 400 with error code VALIDATION_ERROR" -> "The API returns a validation error describing the invalid parameter"

### Priority 5 -- Invariant Hygiene (affects Internal Consistency)

- Step 1: Remove the non-terminal main items invariant (not relevant to team selection).
- Step 4: Replace the non-canonical "API endpoints enforce same permission checks" invariant with journey-sourced invariants.
- Step 3: Add the week-boundary invariant present in Step 2.
