## Conventions Established

1. **Cascade soft-delete pattern** — Delete main items in a single transaction: soft-delete all sub-items first, then main item, with status_history audit trail
2. **Graceful degradation in ViewService** — When optional repo (e.g., statusHistoryRepo) is nil or errors, return data unfiltered rather than failing
3. **Dual-copy component updates** — When a component exists in both item-view and main-item-detail, both copies must be updated in the same task
4. **Permission code seeding** — New permission codes require entries in both codes.go and migration/rbac.go seed data
5. **Form state reset pattern** — Use separate dialog close handlers + mutation onSuccess for clearing; rely on react-query default behavior to preserve state on failure
